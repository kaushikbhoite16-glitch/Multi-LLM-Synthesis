# Multi-LLM Response Evaluation and Adaptive Answer Synthesis System

> A production-quality academic/research prototype for studying multi-LLM response evaluation, quality-cost trade-off analysis, and evaluation-guided adaptive synthesis.

---

## Research Positioning

This platform implements a **RAG-like response synthesis architecture** where the context supplied to a final LLM consists of *evaluated responses generated by other LLMs* — rather than documents retrieved from an external knowledge base.

The research contribution focuses on:
- User-aware, **configurable multi-criteria response scoring** (relevance, correctness, completeness, clarity, consistency, preference match, conciseness, technical depth)
- **Objective resource metric tracking** — input/output tokens, API cost, latency — sourced directly from the OpenRouter API
- **Response conflict detection** and consensus analysis across candidate models
- **Evaluation-guided adaptive synthesis** producing a single user-tailored final answer
- **Empirical baseline comparison** (RQ1-RQ6) against 4 formal baseline architectures

## Pipeline Architecture

```
USER QUERY + PREFERENCES
        ↓
   QUERY ANALYSIS (domain, difficulty, criteria weights)
        ↓
   PARALLEL MULTI-LLM GENERATION (OpenRouter)
        ↓
   USAGE COLLECTION (tokens, cost, latency — API-provided)
        ↓
   RESPONSE NORMALIZATION
        ↓
   SEMANTIC MULTI-CRITERIA EVALUATION (LLM evaluator)
        ↓
   COMPOSITE SCORING (quality + resource penalties)
        ↓
   RANKING
        ↓
   CONFLICT & AGREEMENT ANALYSIS
        ↓
   STRUCTURED CONTEXT FORMATION
        ↓
   FINAL SYNTHESIS LLM (adaptive, user-tailored)
        ↓
   FINAL RESPONSE EVALUATION (+ improvement % vs best candidate)
        ↓
   DATABASE (all intermediate data preserved)
        ↓
   ANALYTICS + EXPERIMENT RESULTS
```

## Quickstart (Local Development)

### Prerequisites
- Python 3.11+ (Python 3.14 tested)
- Node.js v20 LTS (portable install included at `tools/node/`)

### 1. Configure Environment

```powershell
# Copy and edit your API key
copy .env.example backend\.env

# (Optional) Add your OpenRouter key — without it, system uses high-fidelity simulation mode
notepad backend\.env
```

### 2. Start Backend

```powershell
cd backend
.\venv\Scripts\uvicorn.exe app.main:app --host 0.0.0.0 --port 8000 --reload
```

Backend runs at: http://localhost:8000  
API Docs: http://localhost:8000/docs  
Health check: http://localhost:8000/health

### 3. Start Frontend

```powershell
# In a second terminal
$env:PATH = "C:\LLM\tools\node;$env:PATH"
cd frontend
npm run dev
```

Frontend runs at: http://localhost:5173

### 4. Run Tests

```powershell
cd backend
.\venv\Scripts\pytest.exe -v
# 11 tests should pass in ~4 seconds
```

### 5. Run Baseline Experiments

```powershell
cd C:\LLM
.\backend\venv\Scripts\python.exe experiments\runners\run_all_baselines.py
.\backend\venv\Scripts\python.exe experiments\runners\run_evaluator_bias_exp.py
.\backend\venv\Scripts\python.exe experiments\runners\run_cost_quality_exp.py
.\backend\venv\Scripts\python.exe experiments\runners\run_model_diversity_exp.py
```

## Simulation / Demo Mode

When `OPENROUTER_API_KEY` is **not configured**, the system automatically enters **SIMULATION MODE** — clearly marked in the UI with an amber badge.

In simulation mode:
- All candidate responses are generated by a high-fidelity domain-aware mock engine
- Tokens, costs, and latencies are calculated from realistic distributions
- The UI banner displays: **"SIMULATION / DEMO MODE"**
- Mock data is **never** presented as real experimental results

**IMPORTANT**: For actual research results, a valid OpenRouter API key is required.

## Research Questions

---

## Important Principles

1. All API keys are **backend-only** — never exposed to the frontend
2. Token counts and costs come **directly from API** — not estimated
3. The highest-ranked candidate is **not automatically the final answer** — synthesis reasons across all candidates
4. All intermediate pipeline data is **permanently stored** for research reproducibility
5. Mock data is always clearly labelled — real results require an API key
